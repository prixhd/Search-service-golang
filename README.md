# Search Service — HTTP-сервис поиска пользователей на Go

Учебный проект на Go, реализующий HTTP-сервис поиска пользователей и клиент для взаимодействия с ним.

Сервис загружает данные пользователей из XML-файла, поддерживает поиск, сортировку и пагинацию результатов. Клиент отправляет HTTP-запросы, обрабатывает ответы сервера и сообщает о наличии следующей страницы.

Основное внимание в проекте уделено работе с HTTP, обработке XML/JSON, валидации параметров и автоматическому тестированию.

## Возможности

### HTTP-сервер

- Загрузка пользователей из XML-файла.
- Преобразование XML-данных в структуры Go.
- Поиск пользователей по имени и описанию.
- Сортировка по ID, имени и возрасту.
- Сортировка по возрастанию и убыванию.
- Получение результатов без изменения исходного порядка.
- Пагинация с использованием `limit` и `offset`.
- Проверка токена доступа через HTTP-заголовок.
- Валидация параметров запроса.
- Возврат результатов в формате JSON.
- Обработка ошибок чтения и разбора XML.

### HTTP-клиент

- Формирование HTTP GET-запросов.
- Передача параметров поиска через URL.
- Передача токена доступа через заголовок `AccessToken`.
- Ограничение количества пользователей на странице.
- Определение наличия следующей страницы (`NextPage`).
- Обработка HTTP-ошибок.
- Обработка таймаута запроса.
- Декодирование JSON-ответов.

## Технологии

- Go
- `net/http` — HTTP-клиент и сервер
- `encoding/json` — сериализация и десериализация JSON
- `encoding/xml` — чтение XML-данных
- `sort` — сортировка пользователей
- `net/url` — формирование параметров HTTP-запросов
- `testing` — автоматизированное тестирование
- `net/http/httptest` — тестирование HTTP-обработчиков и клиента

Проект использует стандартную библиотеку Go.

## Как работает сервис

1. Клиент получает параметры поиска.
2. Проверяет корректность `limit` и `offset`.
3. Формирует HTTP GET-запрос с параметрами поиска.
4. Добавляет токен доступа в заголовок `AccessToken`.
5. Сервер проверяет токен.
6. Загружает пользователей из `dataset.xml`.
7. Фильтрует пользователей по поисковому запросу.
8. Сортирует результаты по выбранному полю.
9. Применяет пагинацию.
10. Возвращает JSON-массив пользователей.

Клиент преобразует полученный JSON в структуры Go и определяет наличие следующей страницы.

## Параметры поиска

| Параметр | Описание |
|---|---|
| `query` | Подстрока для поиска по имени или описанию |
| `limit` | Максимальное количество пользователей |
| `offset` | Смещение относительно начала результатов |
| `order_field` | Поле сортировки: `Id`, `Name`, `Age` |
| `order_by` | Направление сортировки |

Значения `order_by`:

- `1` — по возрастанию;
- `0` — без сортировки;
- `-1` — по убыванию.

Если поле сортировки не указано, используется `Name`.

Максимальное значение `limit` на стороне клиента — 25.

## Пагинация

Клиент использует подход `limit + 1`.

Например, если запрошено 5 пользователей, клиент запрашивает у сервера 6 записей.

- Если получено 6 записей, клиент возвращает первые 5 и устанавливает `NextPage = true`.
- Если получено 5 или меньше записей, `NextPage = false`.

Это позволяет определять наличие следующей страницы без отдельного запроса на подсчёт всех пользователей.

## Авторизация

Сервер проверяет HTTP-заголовок:

```http
AccessToken: secret
```

Если токен отсутствует или не соответствует ожидаемому значению, сервер возвращает:

```http
401 Unauthorized
```

В проекте используется фиксированный токен для демонстрации механизма проверки доступа.

## HTTP-ответы

Сервер возвращает следующие статусы:

| Статус | Описание |
|---|---|
| `200 OK` | Запрос успешно обработан |
| `400 Bad Request` | Некорректные параметры запроса |
| `401 Unauthorized` | Неверный токен доступа |
| `500 Internal Server Error` | Ошибка чтения или обработки XML |

При успешном запросе сервер возвращает JSON-массив пользователей.

Пример:

```json
[
  {
    "ID": 0,
    "Name": "Boyd Wolf",
    "Age": 22,
    "About": "User description",
    "Gender": "male"
  }
]
```

## Тестирование

Для тестирования используются стандартные пакеты Go:

- `testing`
- `net/http/httptest`

Тесты создают локальный HTTP-сервер и проверяют взаимодействие клиента с сервером без обращения к внешним API.

Проверяются следующие сценарии:

- Успешный поиск пользователей.
- Сортировка по имени, возрасту и ID.
- Сортировка по возрастанию и убыванию.
- Сохранение исходного порядка.
- Проверка токена доступа.
- Обработка неизвестного поля сортировки.
- Отрицательные значения `limit` и `offset`.
- Некорректные числовые параметры.
- Пагинация и выход за пределы набора данных.
- Определение наличия следующей страницы.
- Поиск без результатов.
- Отсутствующий XML-файл.
- Некорректный XML.

### Запуск тестов

```bash
go test ./...
```

### Проверка покрытия

```bash
go test -cover ./...
```

### Подробный отчёт о покрытии

```bash
go test -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
```

## Особенности реализации

- HTTP-клиент и сервер реализованы с использованием стандартной библиотеки Go.
- Поиск, сортировка и пагинация выполняются на стороне сервера.
- Данные загружаются из XML-файла и преобразуются в структуры Go.
- Для тестирования HTTP-взаимодействия используется `httptest.NewServer`.
- Проверяются успешные и ошибочные сценарии работы приложения.

## Ограничения

Проект выполнен в учебных целях.

- Данные хранятся в XML-файле, без использования базы данных.
- XML-файл загружается при каждом запросе.
- Используется фиксированный токен доступа.
- Поиск выполняется с учётом регистра.
- Сервис не предполагает работу с большими объёмами данных.
